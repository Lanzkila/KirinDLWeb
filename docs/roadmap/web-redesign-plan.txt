KIRINDL WEB — WEBSITE REDESIGN PLAN
=================================

Repository: Lanzkila/KirinDLWeb
Related roadmap: docs/roadmap/progress-1-9.md
Status: FRONTEND WIRED TO IMPLEMENTED BACKEND API — PUBLIC BACKEND DEPLOYMENT PENDING

1. MAIN OBJECTIVE
-----------------
Rombak website KirinDL menjadi website khas untuk pengalaman downloader versi web.
Website ini mempunyai identiti dan susun atur sendiri. Reka bentuknya tidak perlu
meniru UI aplikasi Android KirinDL.

Fokus utama website ialah pengguna boleh memasukkan pautan media terus pada website
melalui ruangan input link yang jelas dan mudah digunakan.

2. MAIN WEB INTERFACE
---------------------
- Homepage/web downloader baharu, bukan sekadar reka bentuk Sites Pages lama.
- Input URL/link sebagai elemen utama pada halaman downloader.
- Tindakan Paste, Clear dan Submit/Analyse.
- Maklum balas untuk pautan kosong, format URL tidak sah, dan backend belum disambungkan.
- Metadata dan pilihan format hanya akan ditunjukkan selepas extractor/backend tersedia.
- Jangan dakwa pautan sudah dianalisis atau dimuat turun jika backend belum disambungkan.

3. DESIGN DIRECTION
-------------------
- Reka bentuk khas web desktop dan telefon, responsif dan mudah digunakan.
- Bebas daripada susun atur Android; tidak perlu menyalin skrin atau menu app.
- Utamakan aliran input link dan hasil analisis.
- Pastikan input, butang, status dan mesej ralat boleh digunakan dengan keyboard.

4. EXISTING WEBSITE CONTENT
---------------------------
- Reka bentuk homepage Sites Pages ialah sementara dan dikekalkan sehingga preview baharu disemak.
- Halaman Contact, Issues, Privacy dan Support dikekalkan.
- Laluan halaman maklumat sedia ada perlu kekal berfungsi.
- Semua kerja dibuat dalam repo KirinDLWeb sahaja.

5. TECHNICAL BOUNDARIES
-----------------------
- Repo Lanzkila/KirinDL (Android) tidak boleh diubah untuk kerja rombakan ini.
- Input link frontend bukan bermaksud extractor/downloader sudah tersedia.
- GitHub Pages hanya frontend statik; pemprosesan sebenar memerlukan backend berasingan.
- Login/Register Part 1 ialah UI preview. Jangan hantar atau simpan kata laluan sebelum
  backend autentikasi dan storan selamat tersedia.
- App–Web bridge bukan sebahagian daripada Part 1.

12. ENGINE / DEPLOYMENT LIMITS
------------------------------
- Backend code is in server/kirindl_server/ and can be run through Docker or a Python virtual environment.
- The website frontend only communicates with the backend over HTTP(S); it does not execute Python or FFmpeg in the browser.
- GitHub Pages and Raw.githack are static preview hosts. They do not run the downloader backend.
- public/kirindl-config.js defaults to localhost during local development and remains blank on hosted preview until an HTTPS backend base URL is configured.
- The backend API has passed automated tests, but real source-site downloads, FFmpeg merges, and gallery ZIP outputs still require live validation after a backend host is deployed.
- Current backend state uses one in-memory task manager and one Uvicorn worker. Durable queue, multi-instance scaling, account authentication and metadata/format selection remain future work.
